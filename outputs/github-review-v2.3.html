用实际操作复核

  1. 全库找词。在手册打开原文搜索，范围选全部十书，使用多词同章模式。用空格隔开“天地 圣人”，本次语料有 70 节、涉及 7 本，首项为《庄子》〈天地〉第十二。“逍遥 游”命中 7 节、涉及 2 本，首项为〈逍遥游〉第一。node work/qa-ranked-search.cjs 可核验命中及跳转。
  2. 键盘读书。在 320 像素宽的 Chrome 离线打开手册。普通跨书检索“天下”时，结果状态显示 166 节、10 本书。焦点在输入框时按两次 Tab，再按 Enter 即进入原文阅读区。在“返回搜索结果”上按 Enter，焦点回到搜索框。新模式下检索“天地 圣人”也验证了这条键盘往返路径，并确认搜索控件的名称和结果状态。
  3. 操作游戏。旧版基线的十个被测视图有八个触发了同一条控件命名规则。修复后，测试覆盖桌面和手机各六个阶段。地图关卡按 Esc 关闭后可以继续用键盘操作刚才的节点。在源码仓库运行 npm ci 后用 npm run test:a11y 重跑，需安装 Playwright Chromium 或配置本机 Chrome。
  4. 回到一站选择之前。完成一局并打开结算页。从某站选另一项行动，检查即时的资源变化，再回看该局已经记录的行动与分数。模拟只推算这一步的结果。

检索耗时。本机 Ryzen 7 8845HS、Node 22.23.3 上，2,859 节正文预先归一化用时 122.59 毫秒。“天地 聖人”预热 5 轮后测量 20 轮，排序中位数 2.89 毫秒，第 95 百分位 3.80 毫秒。该数值只计已归一化文本的检索排序，不含浏览器排版。
